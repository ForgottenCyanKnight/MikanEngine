### P0-1 后处理链在 Android 输出 swapchain 纯黑（2026-08-23 定位并修复）
- **根因**：`src/Rendering/PostProcessQuad.cpp` 的 `readFile()` 用 `std::ifstream` 读 `.spv` shader。Android 上 APK assets 不是文件系统，`ifstream` 必然读不到 → `CreatePipeline` 因 shader 代码为空直接 return → `m_Pipeline == VK_NULL_HANDLE` → `PostProcessQuad::Render` 静默 return → 链末 pass 的 render pass 无任何绘制 → 全屏呈现初始布局 UNDEFINED 的内容 = 纯黑。
  - 与 `FullscreenQuad.cpp`（已用 SDL_IOFromFile，Android 正常）对比即见差异。
  - 完美解释此前所有现象：tonemap 纯红诊断仍黑（shader 从未加载，改 shader 输出色无效）；rp/fb 有效、输入解析成功（CPU 侧，均成立）但无绘制；blit 直出正常（blit 不需要 shader pipeline）。
- **修复**：`PostProcessQuad::readFile` 改为与 `FullscreenQuad` 同款的 `SDL_IOFromFile`（`EngineConfig::ResolvePlatformPath` + SDL_IOStream 读取）。
- **渲染路径**：Android 分支从 blit 直出切回 `g_SwapChain.Execute`（tonemap-only 链）→ 输出 `g_CompositeFramebuffers[wd->FrameIndex]`。已补 `CompositeToFinalBarrier`（composite 保持 COLOR_ATTACHMENT_OPTIMAL 采样，布局一致）与 `s_PrevViewProj` 更新。
- **验证**：真机安装运行，画面非黑（白底+彩色模型画面，56 色），链 tonemap pass 每帧执行（日志可见 pass:before 回退 composite = tonemap 输入解析）。用户确认画面正确后收工。
- 改动文件：`src/Rendering/PostProcessQuad.cpp`（readFile）、`src/Core/VulkanManager.cpp`（Android 分支链输出）。

### 模型渲染（根因：ECS namespace extern）
- `SceneSerializer.cpp` / `SceneECS.cpp` 的 `extern ::SceneRenderer g_SceneRenderer;` 原在 `namespace ECS` 内 → 变量被限定为 `ECS::g_SceneRenderer`（8 字节 COMMON）→ 已移到全局作用域。**这是"模型场景崩溃"的真正根因。**

### 黑屏三连（合成路径）
1. **subpassLoad shader 误用**：Android 合成 quad 默认 `fullscreen_subpass.frag.spv`（subpassLoad），独立合成 pass 无 input attachment 读不到 G-Buffer → 显式改 `fullscreen.frag.spv`（texture 版），`g_GameCompositeQuad.Init(..., "fullscreen.frag.spv")`
2. **depth LINEAR 采样**：Adreno 上 depth 格式 + LINEAR 返回垃圾 → 天空判定 `depth>=0.9999` 永假 → 改 `SamplerType::NearestClamp`（FullscreenQuad.cpp infoDepth）。纯绿诊断确认天空分支命中
3. **ECS 双插**：mesh 组件自动补 render + 外部 render JSON 双插 → InsertData 改覆盖语义
