## 2. 标准闭环（构建 → 安装 → 启动 → 日志 → 截图）

```bash
cd "D:\Engine project\vulkan engine\android"

# ① 构建（Release 原生库 + debug APK；增量 ~10s，全量 ~1.5min）
JAVA_HOME="C:/Users/z/.jdks/jbr-21.0.11" ANDROID_HOME="D:/Android studio/sdk" \
  cmd //c "gradlew.bat :app:assembleDebug --console=plain"
# 判断成败：grep "BUILD SUCCESSFUL"；错误看 "error"/"FAILED"

"$ADB" -s 781beb51 install -r android/app/build/outputs/apk/debug/app-debug.apk

# ③ 清日志 + 启动
"$ADB" -s 781beb51 logcat -c
"$ADB" -s 781beb51 shell monkey -p com.mikanengine -c android.intent.category.LAUNCHER 1

# ④ 验证进程存活 + 引擎日志

"$ADB" -s 781beb51 logcat -d -v time MikanEngine:V *:S | tail -30

# ⑤ 截图（Python stdlib 分析颜色，判断画面是否黑屏）
"$ADB" -s 781beb51 exec-out screencap -p > /tmp/screen.png
```

截图颜色分析（无 PIL 时的 PNG 采样脚本，直接可用）：
```bash
python -c "
import zlib, struct
data = open(r'C:\Users\z\AppData\Local\Temp\screen.png','rb').read()
pos=8; w=h=None; idat=b''
while pos < len(data):
    n = struct.unpack('>I', data[pos:pos+4])[0]
    t = data[pos+4:pos+8].decode()
    c = data[pos+8:pos+8+n]
    if t=='IHDR': w,h,_,_ = struct.unpack('>IIBB', c[:10])
    elif t=='IDAT': idat += c
    pos += 12+n
raw = zlib.decompress(idat); bpp=4; stride=w*bpp+1
from collections import Counter
cnt = Counter()
for y in range(0,h,40):
    rs = y*stride+1
    for x in range(0,w,40):
        i = rs+x*bpp
        cnt[(raw[i],raw[i+1],raw[i+2])] += 1
total = sum(cnt.values())
print(f'唯一颜色 {len(cnt)}, 采样 {total}')
for col,c in cnt.most_common(6): print(f'  RGB{col}: {c*100//total}%')
"
```
解读：纯黑(0,0,0)=100% → 黑屏；正常蓝天应有大量蓝色系渐变（唯一颜色数多）。

## 3. 日志要点

- **引擎日志只认 `MikanEngine` tag**：`logcat -d -v time MikanEngine:V *:S`
- **printf/fprintf/std::cout 不进 logcat**！只有 `LOGI/LOGE`（`#include "Core/Log.h"`）进。排查时给关键路径临时加 LOGI。
- 关键正常日志：`Engine assets OK`、`[AtmosphereRenderer] initialized (compute)`、`[CSM]/[PointShadow] ready`、`Swapchain rebuild completed`
- 系统噪音多（小米 logcat 刷屏），必须用 tag 过滤

## 4. 崩溃定位（native SIGSEGV）

```bash
# ① 抓 backtrace（在全部 logcat 里）
"$ADB" -s 781beb51 logcat -d | grep -A12 "backtrace:" | grep "libmikanengine" | head

# ② 找函数符号基址
NM="/d/Android studio/sdk/ndk/25.1.8937393/toolchains/llvm/prebuilt/windows-x86_64/bin/llvm-nm.exe"
"$NM" -C "android/app/build/intermediates/cxx/Release/1q1r6x4i/obj/arm64-v8a/libmikanengine.so" | grep "函数名"

# ③ 符号化（基址 + 偏移）
A2L="/d/Android studio/sdk/ndk/25.1.8937393/toolchains/llvm/prebuilt/windows-x86_64/bin/llvm-addr2line.exe"
"$A2L" -C -f -e <so路径> 0x<基址+偏移十六进制>
```
实测案例：`FullscreenQuad::UpdateDescriptorSet+1384` → 符号化到 `FullscreenQuad.cpp:674`（vkUpdateDescriptorSets）。

## 5. 资产同步（改 engine/ 或 assets/ 后）

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "D:\Engine project\vulkan engine\android\sync_assets.ps1"
```
语义（2026-08-22 版）：
- **全量重建**（先清空 `android/app/src/main/assets`）
- engine/ 资产**拍平到 assets 根**（`shaders/fonts/textures` 直接在根，**无 engine/ 嵌套**——运行时 `GetEngineAssetPath` 安卓分支已去掉前缀）
- 排除 glsl（只打包 spv）；排除桌面大资产（Bistro_v5_2、models/2.0、MetalRoughSpheres、IDKEngine、engine_20260814_pre_csm）

- 脚本必须 UTF-8 BOM

⚠️ **改 assets 后 gradle 可能增量不重打包**（1 秒构建 ≠ 更新）。验证 APK 内文件：
`unzip -p app-debug.apk assets/postprocess_chain_mobile.json | head`，不对就先删 build 或确认 mergeDebugAssets 执行。

## 6. Android 特有陷阱（历史事故清单）

1. **APK assets 不是文件系统**：`std::ifstream`/`fopen`/`std::filesystem::exists` 全部读不到 → 必须用 `SDL_IOFromFile`（相对路径自动 fallback `assets://`）。已修复处：`SceneSerializer::LoadScene`、`TexturePool::LoadRGBEToLinear/GenerateIrradianceMap`、`AtmosphereLUT::CreatePipelines`、`PostProcessChain::LoadFromJson`、`SkyboxRenderer`（目录判断用 `SDL_GetPathInfo`）、**`PostProcessQuad::readFile`（2026-08-23：原用 std::ifstream 导致后处理链末 pass pipeline 未建 → 链输出纯黑，已改 SDL_IOFromFile）**。**新写文件读取代码必须检查这一点**。
2. **Adreno 多 subpass + input attachment 的 vkCreateRenderPass 崩溃** → Android 合成走"几何单 subpass + 独立合成 render pass（texture 采样 G-Buffer）"，不能改回 3 subpass 合并结构。
3. **`g_SceneCompositeQuad` 在 Android 不初始化**（InitCompositeResources 的 `__ANDROID__` 分支只初始化 Game quad）→ 任何调用它的代码必须 `#ifndef __ANDROID__` 保护（历史 SIGSEGV：`UpdateFullscreenQuadDescriptors`）。
4. **二次 `g_AtmosphereRenderer.Init`（swapchain 重建触发）的 LUT Generate `vkQueueSubmit` 返回 `VK_ERROR_DEVICE_LOST`(-4)** → 已加保护：`RecreateSwapChain` 里 `if (!g_AtmosphereRenderer.IsInitialized())` 才 Init。
5. **Android CMake 源码清单曾漏 4 个文件**（GameplayRuntime/GameplayTestMain/RuntimeCapabilities/ThirdPersonCameraSystem）→ 已补齐；**新增 src/*.cpp 必须同步 `android/app/src/main/cpp/CMakeLists.txt`**。
6. 编辑器变量（`s_editorIsGameRunning`）仅 `_WIN32` 声明，Android 引用会编译错（触发条件：该行所在代码被重编）。

## 7. 当前架构状态（2026-08-22）

- **assets 拍平**：APK assets 根 = 引擎资产（shaders/spv 103 个、fonts、textures、skybox、postprocess 配置）+ 精选游戏内容（models/vox,akito,baka,aoi 等），共 ~85M
- **无 glsl 打包**（只 spv）；`postprocess_chain_mobile.json` 当前为 **tonemap-only**（其余 enable:false；完整版备份在 `engine/postprocess_chain_mobile.json.bak`）
- **后处理链与桌面合并**：Android 分支合成 pass 后走 `g_SwapChain.Execute`（与桌面纯游戏模式共用），`InitCompositeResources` 安卓分支构建 Swap 链（mobile 配置）
- **大气渲染已启用**：Android 调用 `RenderSkyRT`（与桌面同条件同参数，内部按太阳方向+海拔 cache，非每帧更新）
- **Android 保留的差异**（合理）：独立合成 pass（Adreno 兼容）、Scene 链/CMAA2 跳过（无编辑器）
- **已修复（2026-08-22 深挖）**：
  - **黑屏根因 ①**：Android 合成 quad 默认 `fullscreen_subpass.frag.spv`（subpassLoad 版）在独立合成 pass（无 input attachment）读不到 G-Buffer → 已显式改 texture 版 `fullscreen.frag.spv`（`InitCompositeResources` Android 分支）
  - **黑屏根因 ②**：深度采样用 LINEAR sampler，Adreno 上 depth 格式+LINEAR 返回垃圾 → 天空判定 `depth>=0.9999` 永假 → 已改 `SamplerType::NearestClamp`（FullscreenQuad.cpp infoDepth）。**纯绿诊断已验证天空分支命中**（用户亲眼确认绿屏）
  - ECS `InsertData` 重复插入仅 assert（Release 无效）→ 已改覆盖语义（include/ECS/ComponentArray.h）
- **遗留问题 A（深坑，未解）**：**静态区踩踏**——`g_SceneRenderer.m_ModelRenderers.size` 被写入指针形状值（this 同族地址），发生在渲染初始化早期（LoadDefaultScene 前），**布局敏感**（每次构建写中/写不中；写中且场景带模型 → PreloadModels find 崩 SIGSEGV；空场景写中也不崩——map 未被读）。桌面同代码正常。已排除：大气 Generate/链 Build/ECS 双插/16KB 对齐/fs::exists/SDL 读/thirdPerson 字段。ASan 尝试失败（wrap.sh 在该机 Android 15 崩在 asan 拦截器自身）。**下次攻关**：修 ASan 环境（或换 MTE 设备/ndk-gdb 远程断点写监视），怀疑方向=某全局数组/静态缓存越界写固定地址
- **遗留问题 B**：画面颜色未最终确认（depth 修复+纯绿验证后未做肉眼终验；screencap 在该机拿黑帧不可信，以肉眼为准）
- 大量【临时诊断】插桩仍在代码中（SceneECS/SceneSerializer/EngineMain Watchdog/FullscreenQuad LOGI/PreloadModels LOGI），搜索"临时诊断"与"DeserializeDiag"可定位；确认后清理
- 改动文件均有 `.bak/.bak2/.bak3` 备份在同目录；`assets/sence.json.bak` = 原始空场景
