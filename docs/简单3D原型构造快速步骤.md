# MikanEngine 简单 3D 游戏原型：快速构造步骤

本文用于快速搭建一个可运行的第三人称 3D 动作原型：玩家、地面、几个方块、相机跟随、动画、碰撞和可选敌人。

## 1. 复制一个已验证场景

优先复制并修改：

```text
assets/third_person_prototype.json
```

保留顶层游戏模块：

```json
{"game": "cesiumwalk"}
```

建议不要从空 JSON 开始。引擎会静默忽略缺失或未知组件，使用已验证场景再删减实体最稳妥。

## 2. 创建最小场景实体

一个可玩的最小原型至少需要：

| 实体 | 必需组件 | 作用 |
|---|---|---|
| Main Camera | `transform`、`camera` | 第三人称跟随和输入 |
| Directional Light | `transform`、`light` | 基础照明 |
| Skybox | `transform`、`skybox` | 天空背景 |
| Ground | `transform`、`mesh`、`render`、`material`、`collider`、`rigidBody` | 地面和静态碰撞 |
| AnimationPlayer | `transform`、`mesh`、`render`、`material`、`animator`、`collider`、`rigidBody`、`script` | 玩家 |

模型实体必须带 `material`。只有 `mesh` + `render` 时，模型可能显示为无纹理纯色。

## 3. 配置地面和方块

视觉模型和碰撞体使用同一组尺寸，避免“看起来贴合但实际穿模”：

```json
"transform": {
  "position": [0, -0.5, 0],
  "scale": [20, 0.5, 20]
},
"collider": {
  "type": 0,
  "size": [2, 2, 2],
  "syncWithModel": true
},
"rigidBody": {
  "type": 0,
  "shapeType": 0,
  "size": [2, 2, 2],
  "mass": 0,
  "useGravity": false,
  "syncWithModel": true
}
```

默认立方体模型范围为 `[-1,1]`，因此上例地面顶部约为 `y=0`。

动态方块改为：

```json
"rigidBody": {
  "type": 1,
  "shapeType": 0,
  "mass": 1.0,
  "useGravity": true,
  "syncWithModel": false
}
```

静态不动方块用离散碰撞即可；玩家和高速物体再按实际速度考虑连续碰撞。

## 4. 配置玩家模型和碰撞体

玩家必须同时具备渲染、动画和物理组件：

```json
"mesh": {
  "type": 4,
  "modelPath": "animations/quaternius/Animation Library[Standard]/Godot/AnimationLibrary_Godot_Standard.glb"
},
"animator": {
  "clipIndex": 9,
  "speed": 1.0,
  "loop": true,
  "playing": true
},
"collider": {
  "type": 2,
  "size": [0.5, 1.2, 0.5],
  "syncWithModel": true,
  "autoFitToModel": true
},
"rigidBody": {
  "type": 1,
  "shapeType": 2,
  "size": [0.5, 1.2, 0.5],
  "mass": 70,
  "useGravity": true,
  "autoFitToModel": true
}
```

推荐使用 `autoFitToModel=true`。引擎会从模型局部包围盒计算胶囊体高度和偏移，不要手动硬编码角色脚底偏移。

玩家脚本绑定：

```json
"script": {
  "scriptName": "PlayerWalkScript",
  "params": {
    "moveSpeed": 5.0,
    "jumpSpeed": 7.0,
    "turnSpeedDeg": 360.0
  }
}
```

若更换模型，先检查模型局部包围盒和自动贴合日志，再调整胶囊半径，而不是直接修改玩家世界位置。

## 5. 配置第三人称相机

Main Camera 的核心配置：

```json
"camera": {
  "isMainCamera": true,
  "thirdPersonEnabled": true,
  "thirdPersonTargetName": "AnimationPlayer",
  "thirdPersonTargetOffset": [0, 0.95, 0],
  "thirdPersonDistance": 6,
  "thirdPersonMinDistance": 2,
  "thirdPersonMaxDistance": 12,
  "thirdPersonYaw": 180,
  "thirdPersonPitch": 12,
  "thirdPersonCollisionEnabled": true,
  "thirdPersonPreserveDistanceWhenOccluded": true,
  "thirdPersonAimEnabled": true,
  "thirdPersonLockOnEnabled": true
}
```

当前原型控制约定：

- `W/S`：沿相机水平前后方向移动。
- `A/D`：沿相机局部左右方向移动。
- 按住鼠标右键：环绕玩家。
- 鼠标滚轮：调整距离。
- `Shift`：瞄准/右肩视角。
- `Q`：锁定带 `LockOnTargetComponent` 的目标。
- 编辑器中只有游戏视图获得焦点时，相机才接收鼠标输入。

玩家脚本在第三人称模式下不能再写相机 Transform；相机 Transform 由 `ThirdPersonCameraSystem` 独占。

## 6. 添加敌人（可选）

敌人至少需要：

```text
mesh + render + material + animator + collider + rigidBody + script
```

脚本绑定为：

```json
"script": {
  "scriptName": "PuppetEnemyScript",
  "params": {
    "detectionRange": 6.0,
    "disengageRange": 10.0,
    "chaseSpeed": 2.6,
    "attackRange": 1.7
  }
}
```

敌人出生点不要紧贴玩家。建议至少相距 `8~10m`，否则 AI 会在第一帧进入追击/攻击，动态胶囊体碰撞会干扰玩家移动测试。

玩家和敌人必须使用不同脚本：

```text
玩家      -> PlayerWalkScript
敌人木偶  -> PuppetEnemyScript
```

## 7. 编译、校验和运行

### 场景校验

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File \
  "D:\Engine project\vulkan engine\tools\validate_scene.ps1" \
  "D:\Engine project\vulkan engine\assets\my_prototype.json"
```

### 编译游戏插件

修改 `games/cesiumwalk/CesiumWalk.cpp` 后：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File \
  "D:\Engine project\vulkan engine\tools\compile_games.ps1"
```

确认正式文件存在：

```text
out/build/x64-Release/Gamecesiumwalk.dll
```

如果 EngineMain 正在运行，编译脚本会生成 `.tmp`。此时必须执行编辑器热重载，或关闭引擎后重新编译；只生成 `.tmp` 不代表运行时已经使用新脚本。

### 交互运行

```powershell
& "D:\Engine project\vulkan engine\out\build\x64-Release\EngineMain.exe" `
  --no-editor `
  --scene "D:\Engine project\vulkan engine\assets\my_prototype.json"
```

### 玩法层固定帧测试

优先使用 CPU-only 测试宿主：

```powershell
& "D:\Engine project\vulkan engine\out\build\x64-Release\MikanTestRunner.exe" `
  --frames 120 `
  --fixed-dt 0.016666667 `
  --dump-state "D:\Engine project\vulkan engine\prototype_state.json" `
  --scene "D:\Engine project\vulkan engine\assets\my_prototype.json" `
  --game cesiumwalk
```

需要验证 Vulkan/渲染链路时，再使用 EngineMain 的 headless 测试。

## 8. 最小验收清单

- 场景加载无 JSON/组件警告。
- 玩家模型有纹理，骨骼动画正常播放。
- 自动生成的胶囊体底部贴近脚底，没有明显浮空或陷入地面。
- 玩家不会因刚体旋转而侧倒。
- 相机在玩家身后，右键环绕和滚轮缩放有效。
- 相机移动到玩家侧面后，W 沿相机前方移动，而不是沿模型初始朝向移动。
- 玩家碰撞体能挡住墙体，地面不会穿透。
- 动态方块能被玩家推动，静态方块保持不动。
- 敌人脚本不会覆盖玩家脚本；敌人远离出生点后再测试 AI。
- 修改脚本后确认加载的是正式 `Gamecesiumwalk.dll`，不是旧 DLL 或残留 `.tmp`。

## 9. 常见问题速查

| 现象 | 优先检查 |
|---|---|
| W 始终沿固定方向 | 是否加载旧 `Gamecesiumwalk.dll`；是否仍有旧脚本写相机 Transform |
| 鼠标移动属性面板时相机也转 | 当前焦点是否在游戏视图；编辑器输入屏蔽是否生效 |
| 模型无纹理 | 是否缺少 `material`，且 `useAlbedoTexture=true` |
| 角色浮空/陷地 | `autoFitToModel`、模型局部包围盒、地面顶部高度 |
| 玩家一出生就被推走 | 敌人是否过近，动态刚体是否在起始位置重叠 |
| 修改脚本没有效果 | 引擎是否锁住 DLL；是否只生成了 `.tmp`；是否完成热重载/重启 |
| 场景实体存在但功能不工作 | 是否漏挂 `script`、`animator`、`collider` 或 `rigidBody` 组件 |

## 推荐构造顺序

```text
复制已验证场景
  -> 先让地面和玩家能加载
  -> 验证自动胶囊体和重力
  -> 配置第三人称相机
  -> 验证相机相对移动
  -> 添加静态/动态方块
  -> 最后添加敌人、锁定和攻击
```

每增加一类功能就运行一次场景校验和固定帧测试，能最快定位是场景配置、插件脚本还是引擎系统造成的问题。
