# VOX 四字节几何与 voxmesh v2

当前常驻 `VoxQuad` 为 4 字节：U8、V8、宽减一8、 高减一8。坐标范围及宽高上限仍为 256 格。法线由方向推导，局部 UV 由顶点角或三角形重心坐标推导，不保存逐顶点 UV 或代表 RGB。

方向和第三维坐标共享在连续平面分组中。GPU/磁盘每组 8 字节：首四边形编号 uint32、平面坐标与方向合并 uint32。平面坐标保存所属体素的轴坐标，正向面解码时加一，因此可以表达坐标 256 的边界面。分组末尾由下一组起点或总四边形数推导；CPU 辅助范围结构包含显式数量，为 12 字节。

栅格 direct/MDI、RT 展开、路径着色、RR 引导和独立验证 shader 共用 `vox_quad_decode.glsl`。GPU 通过四边形编号二分查询平面表，不增加每平面 draw call 或 BLAS geometry；原六方向范围继续用于绘制和 primitive 映射。CPU RT 几何副本也使用 4 字节结构；发光三角形所需颜色从调色板查询。

GPU 几何缓冲的尾部为三个 uint32：平面表 word 偏移、平面组数、栅格属性指针表 word 偏移。栅格缓冲在平面表之前还包含逐四边形属性指针和属性块；RT 几何缓冲只有压缩几何、平面表和尾部，属性位于独立材质缓冲。

颜色与材质仍在共享属性块：4-word header、8-byte 调色板条目、8-byte 四边形描述符、去重的 R8 索引块。纯色面只使用调色板编号。运行时代表材质字仍作为光照兼容数据保留，磁盘 v2 不再重复保存它。4 字节仅指几何，不包含这些属性、平面表、实例或加速结构。

RT BLAS 构建时仍展开为每四边形四个 float3 位置和六个 uint32 索引，共 72 字节临时输入，完成后释放。硬件 BLAS 的内部格式和大小由驱动决定，没有改成四字节三角形。

## 文件布局

显式小端 uint32，magic=0x534d5856，版本=2。前18 words保留 v1 的标识、合并模式、体素数量、四边形数量、属性 word 数、归一化包围盒及六方向四边形数量；接着为平面组数、每组两个 words、每四边形一个 word、完整属性块、末尾 FNV-1a32 校验和。

v1 文件仍可独立读取，加载时恢复新常驻布局，不依赖 VOX 源文件。v2 加载检查尺寸、校验和、连续平面范围、方向数量、几何边界、调色板和 R8 索引。导出仍只执行一次 greedy meshing；加载编译资产不执行 greedy。
